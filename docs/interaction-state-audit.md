# MUNE 交互状态审计

> 审计日期：2026-07-24  
> 审计范围：当前桌面 Web Demo 的真实代码，包括 `app/page.tsx`、`app/globals.css`、`app/layout.tsx`、Mock 数据与本地图片资源。  
> 审计原则：只记录当前代码能够支持的行为；涉及真实后端、文件上传或 AI 模型的内容均标记为待实现建议。

## 审计摘要

当前 MUNE 是一个单路由、纯前端状态驱动的作品集 Demo。所有页面都运行在 `/` 下，通过 `view` 状态切换；没有真实登录、服务端上传、AI 请求、数据库持久化或网络失败处理。

现有代码已经覆盖了主要可演示路径，并具备较完整的默认、Hover、Focus、选中、收藏和部分成功反馈。但异步行为主要由固定计时器或立即跳转模拟，尚未建立统一的 Loading、Disabled、Error、Retry 与重复点击保护。

当前最需要优先解决的不是“给所有页面添加动效”，而是三类可信度问题：

1. 用户提交后是否知道系统正在处理，以及能否安全等待、取消或重试。
2. 页面文案、数据状态和最终结果是否相互一致。
3. 保存、上传和 AI 生成完成后，用户能否明确确认结果去了哪里。

### 全局状态覆盖结论

| 状态 | 当前覆盖情况 | 代码中的实际表现 |
| --- | --- | --- |
| 默认状态 | 已实现 | 所有页面和主要控件均有默认视觉状态。 |
| Hover 状态 | 部分实现 | 侧栏、主要 CTA、推荐卡片、详情 Tab、收藏、衣橱卡片等已覆盖；部分次级按钮和表单选项仅依赖默认浏览器反馈。 |
| Focus 状态 | 基本实现 | 登录页和产品内部按钮、输入框有统一 `focus-visible` 轮廓；弹窗没有焦点管理。 |
| Pressed 状态 | 部分实现 | 黑色主要按钮、添加衣服按钮、收藏按钮、开始试穿有缩放反馈；次级按钮和卡片不统一。 |
| Disabled 状态 | 未实现 | JSX 中没有 `disabled`，CSS 也没有统一 disabled token。 |
| Loading 状态 | 极少量实现 | 上传衣服确认后，按钮文案会变为“正在生成...”；没有 Spinner、进度、`aria-busy` 或不可重复点击状态。 |
| Success 状态 | 部分实现 | 收藏、保存 Look、保存形象、上传自拍通过 Toast 反馈。 |
| Empty 状态 | 部分实现且不一致 | 发现页有“衣橱为空”，衣橱页却始终展示固定内容。 |
| Error 状态 | 基本未实现 | 登录页和 Look 库图片有静态备用图；业务操作没有错误反馈。 |
| Retry 状态 | 未实现 | 当前没有任何业务重试入口。 |
| 重复点击保护 | 未实现 | 上传、保存、Command Bar、个人形象保存均可重复触发。 |
| 返回后状态保留 | 部分实现 | 内部切换时部分 React 状态保留；刷新全部重置，浏览器返回键无法回到上一内部页面。 |

## 1. 当前真实用户流程

### 1.1 页面与状态架构

- 项目只有一个真实路由 `/`。
- `view` 在 `login`、`discover`、`recommend`、`detail`、`tryon`、`wardrobe`、`profile` 之间切换。
- 页面切换不会写入 URL，因此不支持深链接、浏览器前进/后退或刷新恢复。
- 所有登录、上传、生成、保存和个人形象数据只存在于当前 React 组件内存中。
- 刷新页面后回到登录页和初始 Mock 状态。
- 退出登录只切换到登录页，不清空当前会话里的衣橱、收藏或个人形象状态。

### 1.2 登录与进入产品

1. 登录页预填演示邮箱和密码。
2. 用户提交表单后，系统立即进入发现页。
3. 没有真实身份校验、登录 Loading、成功确认或登录失败状态。
4. 邮箱输入框依赖浏览器基础 `type="email"` 行为，但没有 `required`；密码没有校验。
5. 显示密码、注册账号和忘记密码控件目前没有实际行为。

### 1.3 新用户添加衣服

1. 用户登录后看到发现页的新用户状态，文案显示“衣橱为空”。
2. 用户可通过发现页 CTA 或侧栏“添加衣服”打开同一个上传弹窗。
3. 用户可以选择本地图片，也可以点击官方白衬衫案例。
4. 选择本地文件后，系统通过 `URL.createObjectURL` 立即显示预览。
5. 点击“确认上传”后，按钮文案变为“正在生成...”。
6. 固定等待 650ms 后，系统直接进入 AI 推荐页，并显示“已添加白衬衫，正在生成 3 套穿搭”的 Toast。
7. 官方案例不经过等待，直接进入 AI 推荐页。

当前流程没有真实上传、文件校验、衣物识别、生成请求或失败分支。弹窗文案写有“点击或拖拽”，但代码只实现了点击选择文件。

### 1.4 AI 推荐与 Look 详情

1. 推荐页固定展示 3 套 Mock Look。
2. 用户点击任意图片后进入 Look 详情，选中的 Look 被写入 `selectedLook`。
3. 每次从推荐页进入详情时，详情 Tab 默认重置为“本次搭配”。
4. 用户可在“本次搭配”和“穿法教程”之间切换。
5. 收藏按钮可在空心和实心之间切换，并显示“已收藏 Look”或“已取消收藏”Toast。
6. 收藏状态只存在于详情页状态中，不会影响衣橱 Look 库。
7. 详情页没有返回 AI 推荐页的页面内入口。

### 1.5 AI 试穿与保存

1. 用户点击“开始试穿”后立即进入试穿页。
2. 试穿结果是当前 Look 对应的静态图片，没有生成等待。
3. 默认形象和完整形象只改变说明文案，试穿图片本身不变。
4. 用户点击“保存穿搭”后，系统将 Look ID 写入 `savedLookIds`，显示成功 Toast。
5. 450ms 后系统自动进入衣橱 Look Tab。
6. Look ID 会去重，但按钮没有 pending 或 disabled 状态，连续点击会创建多个跳转计时器。

### 1.6 我的衣橱

1. 侧栏进入衣橱时始终默认打开 Look Tab。
2. Look Tab 固定渲染 22 张图片，图片数组与实际 `savedLookIds` 分离。
3. 卡片点击时，系统按照索引循环映射到已保存 Look 数据；卡片画面和打开的 Look 可能不是同一套。
4. 即使没有保存记录，`savedLooks` 也会回退到第一套 Look，因此真实空状态无法出现。
5. 单品 Tab 固定渲染两组 Mock 单品。
6. 点击任意单品都会直接进入同一套通用推荐，不会保留被点击单品的身份。
7. 页面没有首次加载、刷新、空数据、加载失败或重试状态。

### 1.7 我的形象

1. 用户通过头像菜单进入“我的形象”。
2. 身高使用未受控输入框，默认值为 168，但没有写入状态或保存数据。
3. 肤色和身型点击后立即更新本地选中状态。
4. 自拍弹窗支持选择图片和本地预览。
5. 点击“确认上传”后立即关闭弹窗、标记形象已完成并显示 Toast。
6. 点击页面“保存”后立即标记 `profileComplete=true`。
7. 如果从试穿页进入，保存后返回试穿页；从头像菜单进入时，保存后停留在个人形象页。
8. 当前身高、身型、肤色和自拍不会改变推荐数据或试穿图片，只改变完成状态与说明文案。

### 1.8 AI Command Bar

1. 产品内部所有页面顶部都显示 Command Bar。
2. 输入框聚焦后显示两条建议短语。
3. 用户按 Enter 或点击短语后，输入框被清空，弹层关闭。
4. 系统立即进入推荐页，并显示“正在为你生成新的穿搭方案”Toast。
5. 文本包含“白衬衫”时选择第一套 Look；其他所有非空输入都选择第二套 Look。
6. 空输入被静默忽略；无法理解、衣物不存在、网络失败和重试均未实现。

## 2. 交互缺口清单

优先级定义：

- **P0**：用户不知道操作是否生效、结果与操作不一致，或失败后无法继续。
- **P1**：任务可以完成，但过程容易困惑、误操作或失去上下文。
- **P2**：视觉、动效、可访问性和细节完善。

| 页面/组件 | 用户行为 | 当前反馈 | 缺失状态 | 用户可能产生的疑问 | 建议反馈方式 | 优先级 |
| --- | --- | --- | --- | --- | --- | --- |
| 新用户发现页 / 衣橱 | 未上传衣服时进入衣橱 | 发现页显示“衣橱为空”，衣橱页却展示完整 Look 和单品 | 一致的 Empty 状态 | “我的衣橱到底是空的还是已经有内容？” | `isNewUser` 或真实数据为空时，Look 和单品都展示同一套轻量空状态 | P0 |
| 添加衣服弹窗 | 选择非图片、超大图片或损坏图片 | 文件选择器只有 `accept="image/*"` 提示，代码仍直接创建预览 URL | Validation、Error、Retry | “为什么预览是空的？这张图能不能用？” | 选择后立即校验格式、大小和可解码性；错误放在上传区内，保留重新选择入口 | P0 |
| 添加衣服弹窗 | 确认上传后连续点击、关闭弹窗或点击官方案例 | 按钮变为“正在生成...”，但仍可点击；计时器继续运行 | Disabled、重复点击保护、取消规则 | “我已经关闭了，为什么稍后仍然跳到了推荐页？” | 提交后锁定冲突操作；关闭前终止任务或明确提示任务将在后台继续 | P0 |
| AI 分析与生成 | 上传后等待识别衣物并生成 Look | 只有 650ms 固定计时器；结果页已经出现时 Toast 仍写“正在生成” | 分阶段 Loading、Error、Retry | “AI 是已经生成完了，还是还在生成？” | 先显示“正在识别衣物”，再显示推荐页 Skeleton；成功后再展示 3 套结果 | P0 |
| AI 推荐页 | 生成失败或没有合适搭配 | 永远固定展示 3 套 Mock Look | Error、Empty、Retry | “如果 AI 没生成出来，我下一步怎么办？” | 在结果区域内提供原因、保留已上传单品，并提供“重新生成” | P0 |
| AI 试穿页 | 点击“开始试穿” | 立即展示静态结果图 | Loading、Error、Retry、取消或后台处理 | “这是刚生成的结果，还是示例图？” | 首次进入显示试穿生成状态；完成后替换为结果，失败时保留 Look 并支持重试 | P0 |
| 保存穿搭 / Look 库 | 保存后查看衣橱 | 有 Toast 并自动跳转，但 Look 库始终显示固定 22 张图 | 可验证的 Success、真实新增状态 | “刚保存的那套在哪里？是否真的新增了？” | 新保存 Look 应成为可识别的新卡片，并短暂标记“刚刚保存” | P0 |
| AI Command Bar | 输入系统无法理解的需求 | 所有非空文本都会静默映射到第一或第二套 Mock Look | Unrecognized、Clarification、Error | “为什么我输入下雨天，结果却像普通通勤？” | 无法解析时留在输入上下文，给一句澄清提示和可修改示例 | P0 |
| 登录页 | 提交空邮箱、空密码或错误凭据 | 仍可直接登录；密码显示按钮无行为 | Validation、Loading、Error、Disabled | “登录是否真的校验？这个眼睛按钮为什么没反应？” | 基础必填校验；提交时按钮 Loading；错误靠近表单；实现或移除无效控件 | P1 |
| 登录页 | 点击注册账号、忘记密码 | 无反馈 | 跳转或暂不可用反馈 | “是不是按钮坏了？” | Demo 阶段可显示轻量说明，或暂时移除不可演示入口 | P1 |
| 添加衣服上传区 | 拖拽图片到上传区 | 文案承诺支持拖拽，实际没有 drag/drop 事件 | Drag hover、Drop、Error | “为什么拖进去没有反应？” | 实现拖拽；若本轮不做，应删除“拖拽”文案 | P1 |
| 添加衣服上传区 | 选择图片后想更换或查看文件信息 | 只显示预览，主按钮变为确认 | Replace、文件摘要 | “我选的是哪张？如何换一张？” | 预览旁提供“重新选择”，显示文件名或尺寸但不增加复杂编辑器 | P1 |
| AI 推荐页 | 等待期间返回或重新选择单品 | 当前结果立即出现，没有任务上下文 | Cancel、状态保留 | “重新选择后，之前上传的图片还在吗？” | 返回上传弹窗时保留预览；重新生成前明确复用或替换哪件单品 | P1 |
| 推荐卡片 | 点击某套 Look | 立即进入详情，有 Hover 和 Focus | Pressed 或选中反馈较弱 | “我点中了哪一套？” | 保留轻微 pressed，避免额外确认弹窗 | P2 |
| Look 详情 | 想返回 3 套推荐继续比较 | 页面内没有返回入口 | Back、列表上下文保留 | “如何回到刚才的三套方案？” | 增加轻量返回；保留推荐页滚动位置和已选单品 | P1 |
| Look 详情收藏 | 收藏后离开详情 | 爱心与 Toast 会更新，但收藏状态不进入其他页面 | 收藏结果去向 | “收藏后在哪里查看？” | 明确收藏与保存是否同一概念；若无独立收藏库，降低或合并收藏能力 | P1 |
| 穿法教程 | 教程图片加载失败 | 没有备用图或错误占位 | Image Error | “这一步应该怎么做？” | 单张图片内显示可重载占位，不阻塞其他步骤 | P2 |
| AI 试穿保存 | 连续点击“保存穿搭” | ID 会去重，但会重复 Toast 并创建多个跳转计时器 | Pending、Disabled、幂等反馈 | “需要点几次？是不是还没保存？” | 首次点击后按钮进入“保存中”，成功后改为“已保存”再跳转 | P1 |
| AI 试穿 | 完善形象后返回 | 文案变为专属形象，但试穿图片没有变化 | 结果更新 Loading、差异反馈 | “完善信息真的影响结果了吗？” | 如果尚未重新生成，应明确“将在下一次生成中生效”；真正重算时显示局部 Loading | P1 |
| 衣橱 Look | 首次打开或重新加载 | 同步显示固定数据 | Loading、Error、Retry | “内容是在加载还是没有数据？” | 接入数据后首次加载使用网格 Skeleton；失败保留页面骨架和重试按钮 | P1 |
| 衣橱 Look | 点击某张卡片 | 图片和打开的 `savedLooks` 数据按不同数组循环映射 | 结果一致性 | “为什么点这张图，详情却是另一套？” | 每张卡必须由同一 Look 对象提供图片和详情 | P0 |
| 衣橱单品 | 点击具体单品继续搭配 | 所有单品都进入同一通用推荐 | 选中单品反馈、生成上下文 | “AI 有没有使用我点的这件衣服？” | 推荐页明确显示当前单品缩略图和名称；保留该单品 ID | P1 |
| 衣橱 | 在单品 Tab 离开后重新进入 | 侧栏入口强制回到 Look Tab，滚动位置也丢失 | 返回后 Tab 与滚动保留 | “我刚才看到哪里了？” | 会话内记住最后 Tab 和滚动位置 | P1 |
| 我的形象 | 修改身高后保存 | 身高没有进入 React 状态，保存 Toast 仍显示成功 | 数据绑定、Validation、Error | “身高真的保存了吗？” | 将身高纳入表单状态，校验合理范围，失败时不显示成功 | P0 |
| 我的形象 | 修改肤色或身型但未保存就离开 | 选项立即写入全局状态，没有 dirty 或取消概念 | Unsaved、Discard、已保存区分 | “这些选择已经生效了吗？” | 使用草稿状态；保存后提交，离开时仅在确有修改时提示 | P1 |
| 我的形象保存 | 点击保存 | 立即成功，无 pending、失败或重复点击保护 | Loading、Disabled、Error、Retry | “是否已同步到后续推荐和试穿？” | 短按钮 Loading；成功文案说明影响范围；失败保留全部填写内容 | P1 |
| 自拍上传 | 选择非图片、超大图片或上传失败 | 立即预览并在确认后显示“自拍已上传” | Validation、Upload Loading、Error、Retry | “图片是否真的上传完成？” | 与衣物上传复用同一校验和上传状态；失败保留预览 | P1 |
| 头像菜单 | 点击页面其他区域或按 Escape | 菜单通常不会关闭；设置按钮无行为 | Dismiss、Keyboard、暂不可用反馈 | “菜单为什么一直开着？设置是不是坏了？” | 支持点击外部和 Escape 关闭；无功能入口应移除或说明 | P2 |
| 弹窗 | 使用键盘打开、关闭和切换焦点 | 有点击遮罩和关闭按钮，没有 Escape、初始焦点或焦点回收 | Focus trap、Escape、Return focus | “关闭后键盘焦点去了哪里？” | 补齐标准 Dialog 键盘行为，不增加额外步骤 | P1 |
| Toast | 保存、收藏或上传成功 | 视觉 Toast 自动消失 | 可访问 Success、冲突处理 | “屏幕阅读器是否能获知结果？多个 Toast 会不会互相覆盖？” | 使用 `role="status"` / `aria-live`，并统一消息队列或替换规则 | P2 |
| 全局页面切换 | 使用浏览器返回、刷新或复制链接 | 内部页面没有 URL，刷新回到登录和初始状态 | History、恢复、深链接 | “为什么返回键离开了产品？刷新后刚才的结果去哪了？” | Demo 下一阶段至少同步核心 view 与 URL；提交中的草稿存入 session | P1 |
| 退出登录 | 退出后重新登录 | 只切换页面，旧的收藏、衣橱和形象状态仍保留 | Session reset 或明确保留策略 | “这是新会话还是刚才的账号？” | 明确 Demo 策略；真实登录时按账号清理或重新加载数据 | P1 |
| 全局控件 | 异步期间继续点击按钮 | 没有统一 disabled 样式和语义 | Disabled、`aria-busy`、重复点击保护 | “按钮是否还能点？任务是不是启动了两次？” | 建立通用 AsyncButton，只有真实异步操作进入禁用状态 | P1 |

## 3. 异步操作清单

以下等待时间是面向未来真实实现的设计区间，不是当前代码的性能数据。接入具体存储、网络和模型后需要重新测量。

| 操作 | 当前实现 | 可能等待时间 | 是否阻塞页面 | 推荐反馈 | 失败后恢复 | 保留内容 | 是否允许取消 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 登录 | 同步切换到发现页 | 短，通常 0.5–2 秒 | 阻塞提交，不阻塞编辑前状态 | 登录按钮内 Loading，表单保持原位 | 表单内错误并恢复按钮 | 保留邮箱；密码按安全策略决定 | 请求发出后通常无需取消 |
| 本地图片读取与预览 | `createObjectURL` 后立即显示 | 很短，通常低于 1 秒，大图可能更久 | 仅阻塞预览区域 | 上传区局部 Loading 或稳定占位 | 提示无法读取并提供重新选择 | 保留弹窗和之前有效预览 | 可重新选择，相当于取消 |
| 衣物图片上传 | 当前没有真实上传 | 短到中，约 1–10 秒 | 不应锁死整个产品，只锁定当前提交 | 按钮 Loading + 上传区进度；避免虚假百分比 | 内联错误与“重新上传” | 必须保留本地预览和文件 | 应允许取消上传 |
| AI 衣物分析 | 被合并进 650ms 计时器 | 中，约 2–10 秒 | 阻塞生成步骤，不必阻塞侧栏 | 上传弹窗内显示“正在识别衣物” | 说明图片问题并允许换图或重试 | 保留已上传图片 | 可取消并回到预览 |
| AI 生成 3 套 Look | 立即进入固定推荐页 | 中到长，约 5–30 秒 | 不应冻结全页 | 推荐页保留框架，3 个结果位使用 Skeleton，并显示当前单品 | 结果区内错误 + 重新生成 | 保留单品、Command 文本和已完成结果 | 可允许离开；是否后台继续取决于技术方案 |
| AI 试穿 | 立即显示静态结果图 | 长，约 10–60 秒或更久 | 不应强制用户停留 | 试穿画布局部 Loading，说明通常需要等待；完成后原位替换 | 保留 Look 和形象，提供重试 | 保留 Look、默认/专属形象选择 | 建议允许离开后后台继续；真正取消视模型能力决定 |
| 保存 Look | 同步写入本地 state，450ms 后跳转 | 短，约 0.3–2 秒 | 只阻塞保存按钮 | 按钮“保存中”，成功后“已保存”并说明去向 | 按钮附近错误 + 重试 | 保留当前 Look 和试穿结果 | 无需取消，但必须幂等 |
| 加载我的衣橱 | 同步渲染 Mock 数组 | 短到中，约 0.5–3 秒；图片可能渐进加载 | 不阻塞侧栏和 Tab | 首次加载网格 Skeleton；刷新时保留旧内容 | 页面内错误 + 重试 | 保留最后成功数据、Tab 和滚动位置 | 可取消过期请求 |
| 上传自拍 | 本地预览后立即标记成功 | 短到中，约 1–10 秒 | 只阻塞弹窗确认按钮 | 上传按钮 Loading，预览保持可见 | 内联错误 + 重试/重新选择 | 保留本地预览和形象表单 | 应允许取消上传 |
| 保存我的形象 | 同步设置 `profileComplete` | 短，约 0.5–2 秒 | 只阻塞保存按钮 | 保存按钮 Loading；成功后说明后续生效范围 | 表单内错误 + 重试 | 必须保留身高、肤色、身型与自拍 | 无需取消，但要防重复提交 |
| AI Command Bar | 立即进入 Mock 推荐页 | 中，约 3–20 秒 | 不应冻结当前页面 | Command Bar 进入提交态，推荐页显示结果 Skeleton | 保留原始输入，提供修改和重试 | 保留输入文本与当前上下文 | 短请求可不提供取消；长生成允许离开 |
| 图片资源加载 | 浏览器原生加载；登录页和 Look 库有备用图 | 很短到中，取决于网络和图片体积 | 不阻塞页面操作 | 使用固定背景或低调占位，避免布局跳动 | 本地图回退；关键图可提供重载 | 保留其他已加载内容 | 不需要显式取消 |

### 异步设计原则

1. **短操作用按钮反馈**：登录、保存 Look、保存形象不需要全页遮罩。
2. **局部生成用局部 Loading**：衣物分析放在上传弹窗，AI 试穿放在试穿画布。
3. **长生成允许离开**：如果试穿超过十几秒，应允许用户去衣橱或详情页，完成后再恢复结果。
4. **永远保留用户投入**：失败后不能清空上传图片、Command 文本、形象表单或当前 Look。
5. **禁止虚假精确进度**：模型没有可靠百分比时，使用阶段文案和不确定进度动画。
6. **重试应在失败位置发生**：不要用 Toast 代替可操作的错误区域。

## 4. 页面级状态

| 页面 | 已实现状态 | 缺失状态 | 不需要增加的状态 | 容易被过度设计的地方 |
| --- | --- | --- | --- | --- |
| 登录页 | 默认表单、完整 Focus、浏览器基础邮箱格式检查 | 必填校验、登录 Loading、错误、重复提交保护；密码显示按钮未实现 | Skeleton、成功弹窗、多步登录进度 | 第三方登录、复杂注册流程和营销模块不属于当前 Demo 核心 |
| 发现页新用户状态 | 明确的 Empty 文案、主 CTA、Hover/Focus/Pressed | 与衣橱真实数据一致的空状态；用户状态持久化 | 页面 Loading、教程蒙层、多步 Onboarding | 再增加步骤卡、提示气泡或多个入口会削弱“先添加一件衣服” |
| 发现页老用户状态 | 今日 Look、Hover、主要 CTA、Command Bar | 今日推荐加载/失败、刷新后的老用户恢复 | 多推荐列表、筛选器、保存 Toast | 首页不应扩展为资讯流或穿搭瀑布流 |
| 添加衣服弹窗 | 默认、图片预览、模拟上传文案、官方案例、关闭 | 文件校验、拖拽、Loading 锁定、失败、重试、取消规则、重复点击保护 | 多步骤向导、图片编辑器、AI 参数 | 为短流程增加进度条步骤页会让“一件衣服即可体验”变重 |
| AI 推荐页 | 3 套结果、卡片 Hover/Focus、重新选单品 | 生成 Skeleton、失败、重试、当前输入单品上下文 | 无限滚动、排序、复杂筛选 | 为了展示 AI 能力增加十几套结果，会重新制造选择压力 |
| Look 详情页 | Look 选择保留、收藏切换和 Toast、Tab 选中、Hover/Focus、主要试穿入口 | 返回推荐、详情加载失败、收藏去向说明 | 页面级 Loading、评论、分享、相关推荐 | 不要在本页加入多组次级 CTA 或把单品行做成复杂商品详情 |
| 穿法教程 | Tab 即时切换、选中态、从试穿返回时可保留当前 Tab | 教程图片失败占位、必要时的图片重载 | Loading、Toast、完成打卡、教程进度 | 教程是 Look 的解释，不应独立成课程、视频中心或知识库 |
| AI 试穿页 | 默认/完整形象说明、返回 Look、保存成功 Toast 和自动进入衣橱 | 生成 Loading、失败、重试、后台处理、保存 pending、结果是否重新生成的说明 | 身体参数编辑器、对比滑杆、多工具栏 | 过度加入编辑能力会把“确认这套是否适合我”变成图像工作台 |
| 我的衣橱 Look | Tab 选中、卡片 Hover/Focus、图片备用资源、页面滚动 | 真实空状态、首次加载、错误、重试、保存新增可见性、卡片数据一致性 | 每次进入 Toast、每张图 Loading Spinner | 不要给每张卡增加名称、数据和多按钮，当前浏览密度应保留 |
| 我的衣橱单品 | Tab 选中、卡片 Hover/Focus、页面滚动 | 空状态、加载/错误、被点击单品上下文、返回 Tab/滚动保留 | 卡片级操作菜单、批量编辑、持续 Toast | 不要把单品库变成资产管理后台或复杂分类器 |
| 我的形象 | 默认值、肤色/身型选中、自拍预览、保存和上传 Toast、试穿返回路径 | 身高绑定、字段校验、草稿/已保存区分、保存 Loading/Error、自拍上传状态、真正影响结果的反馈 | 强制完成、页面级 Loading、每次选择 Toast | 不要把可选完善变成多页问卷，也不要暴露大量模型参数 |
| 头像菜单 | 展开态、固定 Hover、菜单项 Focus、退出登录 | 点击外部/Escape 关闭、`aria-expanded`、设置项反馈 | Loading、成功 Toast、二级菜单 | 不要把低频入口扩展成完整个人中心导航 |

### 返回与状态保留专项结论

- 从试穿返回 Look 详情时，当前 Look 和详情 Tab 会保留。
- 从试穿进入我的形象并保存时，会返回试穿页。
- 直接从头像菜单进入我的形象并保存时，会停留在我的形象页。
- 从推荐页进入详情后，没有页面内返回推荐页的入口。
- 通过侧栏重新进入衣橱时，总是重置到 Look Tab。
- 页面滚动位置不会被显式保存。
- 上传衣服成功后，`uploadPreview` 没有清空；再次打开弹窗可能继续看到上一次图片。
- 自拍确认后，`profileUploadPreview` 也没有清空；再次打开弹窗仍显示旧预览。
- 刷新会丢失当前页面、保存 Look、收藏、形象和上传预览。
- 浏览器返回键不会在内部页面之间导航。

## 5. 文案缺口

文案只应在用户需要理解系统状态或恢复操作时出现。Tab 切换、普通页面跳转和即时选中不需要 Toast。

| 场景 | 当前文案或行为 | 文案缺口 | 建议文案方向 |
| --- | --- | --- | --- |
| 上传文件要求 | “建议使用纯色背景拍摄衣物。” | 没有格式、大小和可识别性要求 | “支持 JPG、PNG、WebP。请上传完整、清晰的单件衣物照片。”大小上限应以真实实现为准 |
| 文件无效 | 没有反馈 | 不说明原因，也没有恢复动作 | “无法读取这张图片，请重新选择 JPG、PNG 或 WebP 文件。” |
| AI 衣物分析 | 按钮直接显示“正在生成...” | 用户不知道是在上传、识别还是生成 | “正在识别衣物轮廓与类别...” |
| AI 生成 Look | 结果已显示时 Toast 仍写“正在生成” | 系统状态与页面结果矛盾 | 等待时：“正在围绕这件白衬衫生成 3 套 Look...”；完成后：“已生成 3 套 Look” |
| 生成失败 | 没有反馈 | 用户不知道是否应该换图或重试 | “暂时没有生成成功。你可以重试，或换一张更清晰的衣物照片。” |
| Command Bar 空输入 | 静默无动作 | 可以不报错，但缺少提交可用性提示 | 空输入保持不提交即可；提交按钮存在时应保持 disabled，不需要 Toast |
| AI 无法理解输入 | 所有输入都返回结果 | 缺少澄清和修正路径 | “我还没理解你想围绕哪件衣服或什么场景搭配。可以试试‘今天想穿白衬衫’。” |
| AI 试穿等待 | 立即展示静态图片 | 不说明生成需要时间 | “正在生成试穿效果，通常需要一些时间。完成前你可以继续查看这套 Look。”具体时间待真实测量 |
| 默认形象 | “完善我的形象，可获得更准确的试穿效果。” | 没说明默认形象已经能做什么 | “默认形象可用于快速预览；完善身高、身型和自拍后，后续结果会更贴近你。” |
| 完善形象后 | “已使用你的专属形象生成试穿效果。” | 当前图片没有重新生成，文案可能过度承诺 | 若未重算：“形象信息已保存，将用于下一次推荐和试穿。” |
| 保存 Look | “已保存到我的衣橱” | 没说明具体位置，跳转太快 | “已保存到 我的衣橱 · Look” |
| 重复保存 | 仍显示“已保存到我的衣橱” | 没说明之前已经保存 | “这套 Look 已在你的衣橱中。” |
| 衣橱 Look 空状态 | 当前永远不会为空 | 缺少下一步 | “还没有保存的 Look。先查看今日推荐，或上传一件衣服开始搭配。” |
| 衣橱单品空状态 | 当前固定有 Mock 数据 | 缺少下一步 | “还没有衣物。添加一件已有衣服，AI 就能围绕它生成 Look。” |
| 保存形象 | “我的形象已更新” | 没说明影响范围 | “形象信息已保存，将用于后续推荐和试穿。” |
| 保存或加载失败 | 没有反馈 | 没说明数据是否丢失、下一步是什么 | “暂时无法保存。你的填写内容仍在，可以稍后重试。” |

### 文案使用边界

- Loading 文案应描述系统当前动作，不描述抽象 AI 能力。
- Success 文案应说明结果去向，例如“我的衣橱 · Look”。
- Error 文案应同时回答“发生了什么”和“下一步能做什么”。
- Empty 文案只保留一个明确入口，不增加教程步骤。
- 默认形象文案应强调“可以先体验”，避免把完善资料变成前置门槛。
- 不为收藏、Tab 切换、打开弹窗和普通返回重复添加 Toast。

## 6. 最终结论

### 最优先补充的 5 个交互状态

1. **上传校验与可恢复错误**：格式、大小、可解码性校验；失败后保留弹窗并允许重新选择。
2. **AI 分析与生成状态**：区分“识别衣物”和“生成 3 套 Look”，提供 Loading、失败与重试，并阻止重复提交。
3. **AI 试穿长任务状态**：画布局部 Loading、失败重试、离开后的任务恢复，以及默认/专属形象是否重新生成的准确说明。
4. **保存结果可验证状态**：保存按钮 pending、成功去向、重复保存反馈，并让新保存 Look 在衣橱中真实可见。
5. **AI Command Bar 无法理解状态**：保留原输入，提供澄清提示，不再把所有未知输入静默映射到固定结果。

### 最容易被过度设计的 3 个地方

1. 为 650ms 的演示等待制作多步骤进度条或虚假百分比。
2. 为 Tab、收藏、打开弹窗和普通页面跳转同时叠加 Toast、弹窗与动效。
3. 把我的形象扩展成强制问卷、精细身体编辑器或试穿参数面板。

### 推荐实施顺序

1. 先统一异步基础：AsyncButton、InlineStatus、错误与重试规范、重复点击保护。
2. 完成衣物上传校验，并修复上传中关闭弹窗仍会延迟跳转的问题。
3. 接入 AI 生成页 Loading / Error / Retry，再处理 AI 试穿长任务。
4. 修复新用户空状态、保存 Look 与衣橱数据源之间的一致性。
5. 完善 Command Bar 澄清反馈、个人形象保存与衣橱首次加载状态。
6. 最后补齐键盘交互、Toast 可访问性、返回与刷新恢复。

### 可以复用的现有组件

- `primary-btn`：继续作为主要操作，扩展 loading、disabled 和 success 文案。
- `outline-btn`：用于取消、重试和重新选择，不新增更多按钮层级。
- `modal-wash`、`upload-modal`、`profile-photo-modal`：复用为上传与校验错误的承载容器。
- `toast`：保留用于短暂成功反馈，补充 `aria-live`，不用于可操作错误。
- `ai-prompt`、`prompt-popover`：承载 Command Bar 提交态和澄清建议。
- `segmented`、`wardrobe-tabs`：现有选中状态已足够，不需要额外 Loading。
- `home-hero-card`、`look-recommend-grid`、`saved-look-grid`：可以在保持尺寸的前提下承载 Skeleton，避免布局跳动。

### 可能需要新增的通用组件

- `AsyncButton`：统一 Loading、Disabled、重复点击保护和 `aria-busy`。
- `InlineStatus`：在操作发生的位置展示 loading、success、error，不依赖 Toast。
- `RetryPanel`：用于 AI 生成、试穿和衣橱加载失败，保留上下文并提供重试。
- `ValidatedImagePicker`：统一衣物与自拍的格式校验、预览、替换、上传和错误恢复。
- `ResultSkeleton`：为 3 套 Look、试穿画布和衣橱网格提供稳定尺寸占位。
- `LiveToast`：在现有 Toast 上增加消息替换策略和屏幕阅读器播报能力。
